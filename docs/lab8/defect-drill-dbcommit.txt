Учебный дефект «потерян db.commit()» — воспроизведение страховки тестами (ЛР-8)
================================================================================

Описание кейса: docs/lab8/before-after.md, раздел «Кейс "тесты как страховка"».
При первом варианте рефакторинга Д-2 из маршрутов create_dish/update_dish
был потерян db.commit() после replace_ingredients(). В основной ветке дефект
не попал (исправлен до коммита), поэтому по замечанию ревью ЛР-8 кейс
воспроизведён отдельно как доказательство: 16.11.2026.

Как воспроизводится (2 минуты, без изменения истории):

1. В src/main.py закомментировать db.commit() в двух местах
   (после replace_ingredients(...)) — маршруты create_dish и update_dish:

       replace_ingredients(db, db_item.id, item.ingredients)
       # db.commit()   # УЧЕБНЫЙ ДЕФЕКТ: commit потерян

       db.query(Ingredient).filter(Ingredient.dish_id == dish_id).delete()
       replace_ingredients(db, dish_id, item.ingredients)
       # db.commit()   # УЧЕБНЫЙ ДЕФЕКТ: commit потерян

2. Запустить интеграционные тесты ЛР-7:

       python -m pytest tests/test_integration_api.py -v

3. Зафиксировать вывод (ниже), вернуть код: git checkout -- src/main.py
   (в воспроизведении правка вносилась и откатывалась в рабочей копии,
   git diff после отката пуст).

Результат: падают РОВНО 2 интеграционных теста — список покупок и отчёт
перестают видеть ингредиенты блюда (записи остались в незакоммиченной
транзакции и откатились при закрытии сессии). Модульные тесты хелпера
проходят — они проверяют сам хелпер, а не фиксацию транзакции. Вывод:
без страховки тестами регрессия Д-2 дошла бы до релиза незамеченной.
