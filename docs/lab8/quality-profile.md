## Чтение отчёта (по таблице 2 методички)

- **Дублирование.** 30 маршрутов FastAPI повторяют блок
  `db = SessionLocal() / try / … / finally: db.close()` (≈90 строк
  бойлерплейта) — кандидат на вынос в dependency `get_db`.
- **Сложность.** Топ: `init_db` (CC 21), `generate_random_menu` (12),
  `apply_favorite` (11), `get_report` (11), `aggregate_ingredients` (11).
- **Code smells.** Топ строгого профиля: B904 (raise без `from` внутри
  `except`), F401 (неиспользуемые импорты), I001 (порядок импортов).
- **Покрытие.** Ключевые модули покрыты на 100 %; на тяжёлые
  интеграционные сценарии есть 4 теста API.
- **Security hotspots.** SQL-запросы в маршрутах блюд собираются через
  параметризованный `text(...)` с bind-параметрами — инъекций не найдено;
  `random.choice` используется только для генерации меню (не безопасность).

## Вывод

Кодовая база в целом здорова (0 замечаний в CI-профиле, 100 % покрытие
ключевой логики), но технический долг концентрируется в `main.py`
(2244 строки): копипаста сессий в 30 маршрутах, дублирование сохранения
ингредиентов блюд, функция `init_db` с CC 21 и встроенный HTML-шаблон
(~1600 строк). Эти позиции перенесены в реестр технического долга
(`tech-debt-registry.md`).
