# Классификация замечаний статического анализатора по ISO/IEC 25010

ЛР-8, шаг 3. Источники замечаний: расширенный профиль ruff
(`ruff-strict.toml`, полный список — `ruff-strict-report.txt`) и
скрипт метрик `scripts/code_metrics.py` (сложность и дублирование).

Характеристики модели ISO/IEC 25010, использованные в классификации:
**сопровождаемость** (модифицируемость, тестируемость), **надёжность**
(отказоустойчивость), **функциональная пригодность** (функциональная
корректность), **производительность** (ресурсоёмкость), **удобство
использования** (защита от ошибок пользователя).

| № | Замечание | Источник | Характеристика ISO 25010 | На что влияет | Решение |
|---|---|---|---|---|---|
| З-1 | 30 маршрутов повторяют блок `SessionLocal()/try/finally` — дублирование ≈ 90 строк | `main.py`, все маршруты | Сопровождаемость | Новые маршруты легко пишут с утечкой сессии: забытый `db.close()` → исчерпание соединений → надёжность | **Исправляем** (Д-1: dependency `get_db`) |
| З-2 | Копипаста вставки ингредиентов блюда: одинаковый цикл `INSERT + _ensure_product` в двух маршрутах | `main.py:2085–2094`, `main.py:2120–2129` | Сопровождаемость → функциональная пригодность | Правки в двух местах расходятся: например, исправят валидацию в одном маршруте и забудут во втором → некорректные данные | **Исправляем** (Д-2: общий хелпер) |
| З-3 | `init_db` — цикломатическая сложность 21 (создание таблиц + наполнение CSV + ветвления) | `main.py:24` | Сопровождаемость (тестируемость) | Функцию невозможно протестировать по частям; любая правка схемы — риск для инициализации БД | **Исправляем** (Д-3: разбить) |
| З-4 | `generate_random_menu` — CC 12: разбор даты, валидация дней, группировка, выбор блюда, апсерт меню в одном методе | `main.py:1813` | Сопровождаемость | Вероятность регрессии при правках логики генератора меню | **Исправляем** (Д-4: выделить выбор блюда) |
| З-5 | B904: `raise HTTPException` внутри `except` без `from` — теряется исходная причина ошибки | `main.py:1819, 1941, 2009` | Надёжность (отказоустойчивость) | При разборе инцидентов в логе нет первопричины — дольше локализуется сбой | **Исправляем** (добавить `from None`, т.к. причина уже превращена в понятное сообщение API) |
| З-6 | F401: неиспользуемые импорты `io`, `pydantic.BaseModel`, `schemas.DishIngredient` | `main.py:4, 9, 17` | Сопровождаемость (+ производительность старта) | Читатель ищет смысл в импорте, которого нет; лишние модули при старте | **Исправляем** |
| З-7 | I001: несортированные импорты в 5 файлах | `build_app.py`, `database.py`, `export_strategies.py`, `models.py`, `main.py` | Сопровождаемость | Шум в diff'ах при добавлении импортов вручную | **Исправляем** (`ruff --fix`) |
| З-8 | W291: пробельные символы в конце строк | `build_app.py:21–23` | Сопровождаемость | Мусор в diff'ах | **Исправляем** (`ruff --fix`) |
| З-9 | Агрегация в `get_report` повторяет семантику `shopping_calc.aggregate_ingredients` (свои словари, свой ключ) | `main.py:2422–2432` | Сопровождаемость | Логика агрегации живёт в двух местах — при изменении правил учёта порций легко обновить только одно | **Оставляем осознанно**: отчёт считает только числовые позиции и возвращает числа (UI строит таблицу), список покупок — числа и «по вкусу»; объединение изменит контракт API отчета перед релизом. Фиксируем в остаточном долге |
| З-10 | HTML-шаблон UI (~1600 строк) встроен строкой в `main.py` (64 % файла) | `main.py:153–1753` | Сопровождаемость (модифицируемость) → удобство использования | Любая правка UI требует открывать файл бэкенда; конфликтует с правками API | **Оставляем осознанно**: извлечение в файл ломает сборку PyInstaller (`--add-data`), которую нет возможности проверить на всех машинах перед релизом. План — ЛР-9 (весна) |

Примечание по З-5: правило B904 фиксирует и потенциальные Security
hotspots-подобные места — «проглатывание» причины исключения; решено
компромиссом `from None`, потому что для пользователя API текст
`HTTPException` уже человекочитаем, а стектрейс причины в лог не нужен.

## Итог

Классификация подтвердила: почти весь долг проекта сосредоточен в
характеристике **«сопровождаемость»** (8 из 10 замечаний), точечно —
**надёжность** (З-5) и **функциональная пригодность** (З-2). Прямых
замечаний к безопасности и производительности строгий профиль не дал;
SQL-конструирование проверено вручную — параметризованные запросы
(`text(...)` с bind-параметрами), инъекций нет.
