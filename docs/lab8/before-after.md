## Погашенные позиции и их измеримый эффект

| Позиция | Что сделано | Как видно в метриках |
|---|---|---|
| Д-1 | Dependency `get_db`: маршруты получают сессию через `db=Depends(get_db)` | −90 строк бойлерплейта; дублирование блоков сессии = 0; новый маршрут физически не может «забыть» `db.close()` |
| Д-2 | Хелпер `replace_ingredients` (общий код create/update dish) | Удалён скопированный цикл INSERT из двух маршрутов; покрыт 2 модульными тестами |
| Д-3 | `init_db` (CC 21) разбит на `_ensure_servings_column`, `_seed_default_menu`, `_seed_dishes_from_csv`, `_seed_default_products` | Orchestrator `init_db` — CC 1; максимум по проекту снижен с 21 до 12 |
| Д-4 | Выбор блюда вынесен в `pick_dish_for_meal`, группировка — в `_group_dishes_by_category` | CC `generate_random_menu`: 12 → 8; логика выбора покрыта 2 модульными тестами |
| З-5…З-8 | `raise ... from None` (3 места), неиспользуемые импорты, порядок импортов, хвостовые пробелы | Строгий профиль ruff: 15 → 0 замечаний |

## Кейс «тесты как страховка» (требование методички)

При рефакторинге Д-2 первый вариант коммита потерял `db.commit()` после
вставки ингредиентов — **интеграционные тесты ЛР-7 сразу поймали дефект**
(2 теста упали: список покупок и отчёт перестали видеть ингредиенты).
Это наглядно подтверждает тезис из рекомендаций преподавателя:
рефакторинг без страховки тестами — риск, а с ней — безопасная процедура.
Дефект был исправлен до коммита, в историю он не попал.

## Выводы

1. Погашение четырёх позиций долга не изменило ни одного контракт API —
   все 43 теста зелёные, в т.ч. интеграционные сценарии ЛР-7.
2. Кодовая база сократилась на 69 строк при добавлении 4 новых тестов —
   рефакторинг окупился объёмом.
3. Остаточный долг — 3 функции с CC 10–12 (`_seed_dishes_from_csv`,
   `apply_favorite`, `get_report`) и HTML-монолит; их судьба описана
   в `accepted-debt.md`.
