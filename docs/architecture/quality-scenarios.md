# Разбор качественных сценариев (архитектурное ревью)

## Сценарий 1: Пиковая нагрузка на данные (Связь с НФТ-2)
**Ситуация:** Пользователь загружает расширенный справочник из 1000 рецептов и нажимает «Сформировать список покупок на месяц» (30 дней).
**Ожидание:** Система должна выполнить суммирование ингредиентов (блок IDEF0 A3.2) не дольше чем за 3 секунды.
**Анализ архитектуры:** Асинхронный FastAPI обрабатывает запрос. SQLite выполняет быстрые SELECT-запросы по индексированным полям (`dish_id`). Агрегация происходит в памяти Python. Сценарий выдерживается. Если время превысит 3 с, потребуется внедрение кэширования (Redis).

## Сценарий 2: Отказ узла (Связь с НФТ-4)
**Ситуация:** Аварийное закрытие браузера или отключение питания во время редактирования меню (блок A1).
**Ожидание:** Введенные данные не должны быть утеряны.
**Анализ архитектуры:** Каждое изменение в меню (добавление блюда в ячейку) отправляет POST/PUT запрос на бэкенд, который сразу делает `commit` в базу SQLite. Данные физически записываются на диск. При перезапуске данные сохраняются.
