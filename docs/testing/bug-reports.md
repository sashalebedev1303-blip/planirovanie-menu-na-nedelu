## № 1. Список покупок: дробное количество выводится с точкой

- Issue:(https://github.com/sashalebedev1303-blip/planirovanie-menu-na-nedelu/issues/120) ; статус: закрыт (fix: a615cda)
- **Приоритет:** низкий; **версия:** v0.1.0

**Шаги воспроизведения:**
1. Добавить блюдо с ингредиентом «Молоко — 0,25 л».
2. Добавить в меню день с этим блюдом и 2 порциями.
3. Нажать «Сформировать из меню» (список покупок).

**Исправление:** `format_quantity()` в `src/shopping_calc.py` печатает дробь
с запятой; проверено тестом `test_aggregate_fractional_quantity_formatted_with_comma`
и интеграционным `test_menu_servings_to_shopping`.

## № 2. Отчёт: количество с запятой («50,5») считается как 0

- Issue: (https://github.com/sashalebedev1303-blip/planirovanie-menu-na-nedelu/issues/121) ; статус: закрыт (fix: b43e6f3)
- **Приоритет:** высокий; **версия:** v0.1.0

**Шаги воспроизведения:**
1. Добавить блюдо с ингредиентом «Молоко — 50,5 мл».
2. Добавить день и 2 порции.
3. Открыть полный отчёт `/api/report`.

**Ожидаемое:** в summary суммарное количество 101.

**Факт:** 0 — эндпоинт парсил количество через `float()`, который не понимает
запятую, и молча обнулял позицию.

**Исправление:** в `/api/report` используется тот же `parse_quantity`, что и
в списке покупок; проверено интеграционным тестом
`test_report_counts_comma_decimal_quantities`.

## № 3. День меню: meal_type не валидируется

- Issue: (https://github.com/sashalebedev1303-blip/planirovanie-menu-na-nedelu/issues/122) ; статус: закрыт (fix: b43e6f3)
- **Приоритет:** средний; **версия:** v0.1.0

**Шаги воспроизведения:**
1. Отправить `POST /api/menu` с `meal_type: "supper"`.

**Ожидаемое:** 422 — валидных приёмов пищи четыре (завтрак, обед, ужин,
перекус), запись с «supper» не отображается ни в одном столбце таблицы.

**Факт:** 200 — запись сохранялась в БД и «висела» невидимой.

**Исправление:** в `src/schemas.py` для `MenuItemCreate.meal_type` добавлен
`Literal["breakfast", "lunch", "dinner", "snack"]`; проверено
`test_menu_form_validation_and_save`.
