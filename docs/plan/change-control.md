# Процедура контроля изменений

## Алгоритм

| Шаг | Действие | Ответственный |
|---|---|---|
| 1 | Заявка на изменение подаётся в GitHub Issues с меткой `change-request` | Любой участник |
| 2 | Анализ влияния на сроки, трудозатраты и риски | Лебедев (аналитик) |
| 3 | Решение: принять / отклонить / отложить в бэклог следующего спринта | Николаев (РП) + заказчик |
| 4 | Обновление ИСР, словаря, графика и трассировки | Ответственный за пакет |
| 5 | Фиксация изменения в протоколе встречи и в `docs/plan/` | Лебедев |

## Согласование с процессом изменений в ПИ (ЛР4)

Новые требования сначала попадают в бэклог. Изменение текущего спринта —
только по правилам Scrum.

## Журнал изменений (change request log)

Ведётся в GitHub Issues с меткой `change-request`.
