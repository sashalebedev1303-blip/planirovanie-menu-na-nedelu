# Заметки о релизе v1.0.0

**Дата:** 21.11.2026
**Тег:** `v1.0.0`
**Тип:** первый стабильный релиз сквозного проекта (итог ЛР-1…ЛР-9).

## Что нового

- **Планирование меню на неделю:** составление меню по дням, четыре приёма
  пищи (завтрак, обед, ужин, перекус), количество порций для каждого приёма.
- **Справочник блюд:** стартовый каталог из `dishes.csv`, добавление,
  редактирование и удаление своих блюд вместе с ингредиентами.
- **Справочник продуктов:** категории, единицы измерения, поиск, импорт
  продуктов из ингредиентов блюд.
- **Автоматический список покупок:** сводный расчёт по меню с учётом порций,
  объединение одинаковых ингредиентов, отметка «куплено», ручное
  добавление и редактирование позиций.
- **Экспорт и отчёты:** список покупок в TXT и CSV, печать отчёта,
  стратегии экспорта (паттерн «Стратегия», OCP).
- **Случайное меню** на диапазон дат и **дублирование дня** на другую дату.
- **Избранное:** сохранение меню за период как шаблона и применение шаблона
  к любой дате с защитой от перезаписи.
- **Поиск и фильтрация** блюд по названию и категории, тёмная тема.
- **Инженерная инфраструктура (ЛР-9):** единый конвейер GitHub Actions
  `lint → tests → build → docker`, воспроизводимый артефакт сборки,
  контейнерный образ и публикация в GHCR, защита ветки `main`.
- **Контейнеризация:** `Dockerfile` на `python:3.12-slim`, запуск от
  непривилегированного пользователя, healthcheck, том для SQLite-базы.
- **Параметры запуска через окружение:** `HOST`, `PORT`, `OPEN_BROWSER`,
  `DATABASE_PATH` — один и тот же код работает и на рабочей станции,
  и в контейнере.

## Исправления

- Устранены 15 замечаний строгого профиля ruff (B904, F401, I001, W291);
  CI-профиль остаётся зелёным.
- `init_db` разбит на четыре хелпера: цикломатическая сложность снижена
  с 21 до 1, максимум по проекту — с 21 до 12.
- Сессия БД выдаётся через зависимость `get_db` — исключены «забытые»
  `db.close()` в 30 маршрутах.
- Устранён дубликат вставки ингредиентов в `create_dish`/`update_dish`
  (общий хелпер `replace_ingredients`).
- Восстановлен `db.commit()` после вставки ингредиентов — дефект поймали
  интеграционные тесты (кейс «тесты как страховка», см.
  `docs/quality/defect-drill-dbcommit.txt`).
- Проверена валидация прошедшей даты и обязательных полей формы.

## Известные ограничения

- **Один пользователь и SQLite.** Приложение рассчитано на локальный
  однопользовательский режим; многопользовательский кабинет и серверная
  СУБД — следующая итерация (ADR-001, О-4).
- **HTML-интерфейс встроен в `main.py`** (~1600 строк): вынос в отдельные
  файлы запланирован на следующую доработку UI (О-1).
- **Четыре функции с цикломатической сложностью 11–12**
  (`_seed_dishes_from_csv`, `apply_favorite`, `get_report`,
  `aggregate_ingredients`) оставлены осознанно; при следующей правке
  каждой из них сложность приводится к ≤ 10 (О-3, Д-7).
- **Покрытие измеряется для ключевых вычислительных модулей**
  (`shopping_calc`, `quantity` — 100 %); `main.py` с HTTP-маршрутами и
  HTML-шаблоном в порог покрытия не входит (осознанное ограничение).
- **Облачное развёртывание не автоматизировано:** поддерживается локальный
  запуск из контейнера; инструкция — в `README.md`.
- **SonarCloud не подключён** (нет доступа к аккаунту владельца);
  используется ruff + собственный скрипт метрик и прогон SonarQube
  Community Build в CI (О-5).
- **Windows-сборка без цифровой подписи:** SmartScreen может показать
  предупреждение при первом запуске `.exe`.

## Как запустить

### Вариант 1. Контейнер (рекомендуется)

```bash
docker pull ghcr.io/sashalebedev1303-blip/planirovanie-menu-na-nedelu:1.0.0
docker run --rm -p 8000:8000 -v tastyweek-data:/app/data \
  ghcr.io/sashalebedev1303-blip/planirovanie-menu-na-nedelu:1.0.0
```

Открыть <http://localhost:8000>. База хранится в томе `tastyweek-data`.

### Вариант 2. Из исходников

```bash
python -m pip install -r src/requirements.txt
cd src && python main.py
```

### Вариант 3. Windows-сборка

Скачать `TastyWeek_v1.0.zip` из релиза `v1.0`, распаковать, запустить
`dist/TastyWeek/TastyWeek.exe` (при предупреждении SmartScreen —
«Подробнее» → «Выполнить в любом случае»).
