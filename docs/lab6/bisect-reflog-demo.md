# Демонстрация восстановления: `git bisect` и `git reflog` (ЛР-6, продвинутый уровень)

Цель шага — показать, что регресс, найденный тестами, откатывается
воспроизводимо: сначала локализуем коммит-виновника бисектом,
потом показываем восстановление позиции через `git reflog`.

## Подготовка

Для демонстрации была отведена временная ветка
`feature/lab6-recovery-demo` (в `main` она не сливалась и после демо
удалена, чтобы сломанный код не попал в общую историю).

На ветке три коммита:

| Хеш | Сообщение | Состояние тестов |
|---|---|---|
| `2d53dab` | Добавить черновик примечаний к демо bisect | `13 passed` |
| `d32c78b` | Править заголовок текстового экспорта | **`2 failed`** — сломан заголовок `TxtExportStrategy` |
| `bfd2dec` | Обновить черновик примечаний | `2 failed` |

## Шаг 1. Локализация виновника: `git bisect`

Используем тесты как критерий «хорошо/плохо»: коммит, на котором
`python -m pytest tests -q` падает — плохой.

```
> git bisect start HEAD d8b6b91
# bad:  bfd2dec  Обновить черновик примечаний
# good: d8b6b91  Добавить тесты стратегий экспорта и разбора количества
Bisecting: 0 revisions left to test after this (roughly 1 step)
[d32c78b] Править заголовок текстового экспорта

> git bisect run python -m pytest tests -q
Bisecting: 0 revisions left to test after this (roughly 0 steps)
d32c78b305cb... is the first 'bad' commit
```

`git bisect run` бинарным поиском перешёл к подозреваемому коммиту,
запустил тесты, получил не нулевой код выхода и продолжил — за один
шаг вернул виновника:

```
d32c78b «Править заголовок текстового экспорта» is the first 'bad' commit
```

Полный журнал бисекта (`git bisect log`):

```
# bad: [bfd2decca25e6614...] Обновить черновик примечаний
# good: [d8b6b91a1f9157da...] Добавить тесты стратегий экспорта и разбора количества
git bisect start 'HEAD' 'd8b6b91'
# bad: [d32c78b305cbcaf5...] Править заголовок текстового экспорта
git bisect bad d32c78b305cbcaf5e75eefe8d6710f0c75ca59ba
# good: [2d53dabe7fe1a60...] Добавить черновик примечаний к демо bisect
git bisect good 2d53dabe7fe1a60a6c57c2707ea88b54bd45874b
# first 'bad' commit: [d32c78b305cbcaf5...] Править заголовок текстового экспорта
```

## Шаг 2. Выход из бисекта

```
> git bisect reset          # возвращаемся на исходную ветку
> python -m pytest tests -q
2 failed, 11 passed         # ожидаемо: HEAD демо-ветки — сломанный коммит
```

Виновник определён: коммит `d32c78b` `Править заголовок текстового
экспорта` случайно заменил заголовок `"СПИСОК ПОКУПОК"` на
`"Список покупок"`, на который завязаны тесты. Восстановление —
`git revert d32c78b` (или `reset --hard` до него на неслитой ветке).

## Шаг 3. Журнал перемещений: `git reflog`

После бисекта в журнале остаётся вся хронология, включая коммиты
удалённой далее ветки:

```
> git reflog -7 --oneline
bfd2dec HEAD@{0}: checkout: moving from 2d53dab... to feature/lab6-recovery-demo
2d53dab HEAD@{1}: checkout: moving from d32c78b... to 2d53dab...
d32c78b HEAD@{2}: checkout: moving from feature/lab6-recovery-demo to d32c78b...
bfd2dec HEAD@{3}: commit: Обновить черновик примечаний
d32c78b HEAD@{4}: commit: Править заголовок текстового экспорта
2d53dab HEAD@{5}: reset: moving to 2d53dab...
4c4ee85 HEAD@{6}: commit: Обновить черновик примечаний
```

Если ветку случайно удалили, коммит всё равно восстанавливается
по хешу из `reflog`:

```
> git branch feature/lab6-recovery-demo bfd2dec
```

## Мини-шпаргалка

| Команда | Назначение |
|---|---|
| `git bisect start bad good` | начать бинарный поиск между плохим и хорошим коммитами |
| `git bisect run <команда>` | автоматически отмечать коммиты по коду выхода |
| `git bisect reset` | выйти из бисекта, вернуться на исходную позицию |
| `git reflog` | журнал перемещений HEAD — карта восстановления |
| `git branch <имя> <хеш>` | восстановить ветку по хешу из reflog |
