# Заметки о составе версии — тег v0.1.0 (ЛР-6)

Тег `v0.1.0` фиксирует состояние проекта на этапе ЛР-6 «Реализация и
Git-workflow»: стандарты кодирования, SOLID, «Стратегия», тесты и
командный Git-процесс, внедрённые на этом этапе, применяются и на
последующих этапах.

> Примечание: тег `v1.0` ранее был поставлен на сборку прототипа из
> раздела Releases (артефакт `TastyWeek_v1.0.zip`). Тег `v0.1.0`
> начинает новую поэтапную линейку тегов практики ЛР-6 — он фиксирует
> состояние кода на момент завершения ЛР-6.

## Состав версии v0.1.0

### Функциональность

- Составление меню по дням недели из базы блюд и добавление своих
  (`src/main.py`, справочник `src/dishes.csv` — 2373 строки);
- автоматическая генерация списка покупок из меню с учётом порций;
- просмотр/редактирование списка покупок, отметка «куплено»;
- экспорт списка покупок по паттерну «Стратегия»
  (`TxtExportStrategy`, `CsvExportStrategy`, реестр `STRATEGIES` —
  `src/export_strategies.py`);
- избранное-шаблоны меню, дублирование дней, случайная генерация;
- тёмная тема, поиск блюд, справочник продуктов.

### Архитектура и качество (ЛР-5 → ЛР-6)

- Слои по SOLID: `database.py` (подключение), `models.py` (таблицы),
  `schemas.py` (валидация), `main.py` (только маршруты, SRP);
- стандарт кодирования PEP 8 + линтер ruff (`ruff.toml`),
  CI-проверка (`.github/workflows/ruff.yml`);
- тесты стратегий экспорта и разбора количества (`tests/`, pytest);
- pre-commit хук с линтером (`.pre-commit-config.yaml`,
  `requirements-dev.txt`).

### Процесс (ЛР-6)

- модель ветвления GitHub Flow (`feature/*`, `docs/*`, `fix/*`),
  правила коммитов и PR — `CONTRIBUTING.md`;
- история PR по задачам участников (#99–#102) со ревью —
  `docs/lab6/contribution-summary.md`;
- документированное разрешение конфликта слияния —
  `docs/conflict-resolution.md`;
- отчёт о SOLID-рефакторинге и обоснование «Стратегии» —
  `docs/refactoring.md`;
- демо `git bisect` / `git reflog` — `docs/lab6/bisect-reflog-demo.md`.

## Как выпустить релиз на GitHub

1. Поставить аннотированный тег на текущее состояние `main`:

   ```
   git tag -a v0.1.0 -m "Прототип этапа ЛР-6: стандарты кодирования, SOLID, Стратегия, Git-workflow"
   git push origin v0.1.0
   ```

2. Открыть раздел **Releases** → **Draft a new release** → выбрать тег
   `v0.1.0` → заголовок «v0.1.0 — этап ЛР-6» и описания выше.
3. Приложить артефакты сборки, если требуются (архив прототипа
   аналогично разделу Releases `v1.0`).
