# Правила работы над проектом «ИС планирования меню на неделю»

Документ описывает обязательные правила командной работы над проектом.
Они действуют с первой лабораторной работы и до защиты сквозного проекта.

## Ветвление

Основная ветка — `main`. **Прямые коммиты в `main` запрещены.**

Любое изменение — в отдельной ветке с осмысленным именем:

- `feature/<название>` — новая функциональность
  (например, `feature/menu-week-view`, `feature/shopping-list-generator`);
- `docs/<название>` — документация
  (например, `docs/meeting-template`, `docs/readme-update`);
- `fix/<название>` — исправление ошибки
  (например, `fix/duplicate-ingredients`).

Ветка живёт до слияния в `main`, после слияния удаляется.

## Коммиты

Сообщение коммита — в повелительном наклонении, по делу:

- «Добавить форму выбора блюд на неделю»
- «Исправить суммирование повторяющихся ингредиентов»
- «Обновить README с описанием проекта»

Коммит должен решать одну задачу; большие изменения дробятся
на серию небольших коммитов.

## Pull request

Любое изменение попадает в `main` только через pull request (PR).

В PR обязательно:

- заголовок в повелительном наклонении;
- описание: что сделано, зачем, как проверить;
- назначенный ревьюер из команды (не автор PR);
- ссылка на задачу трекера, если есть (например, `Closes #3`).

Ревьюер проверяет изменения и ставит **Approve** или **Request changes**.
Только после Approve PR сливается в `main`.
